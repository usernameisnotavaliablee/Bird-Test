# 喜鹊改版 APK 解包分析报告

> 分析对象：`改版.apk` vs `原版.apk`
> 分析方法：解包 → 结构对比（archive/manifest）→ jadx 源码归一化 diff → smali 复核
> 分析日期：2026-09-01

## 结论总览

改版对原版做了**两类改动**：

1. **签名绕过**（规避原版签名校验，使重打包可安装运行）
2. **业务逻辑篡改**：绕过"觅Ta"服务开关校验，强制查看他人课表/信息

---

## 一、结构层差异（archive / manifest 对比）

### 原版 = 加固包
- Manifest 的 application 入口为 `com.nesun.stub.ZAP`（加固壳桩），真实业务代码被抽取到加固 payload（`original/payload_dex/` 共 5 个 dex）。
- 签名证书：`META-INF/KINGOKEB.RSA`。

### 改版 = 对原版的二次重打包
| 差异 | 详情 |
|---|---|
| 签名证书 | `KINGOKEB` → `ANDROID`（`META-INF/ANDROID.RSA/.SF`） |
| 签名绕过注入 | `libSignatureKiller.so`（arm64-v8a / armeabi-v7a / armeabi 三 ABI）+ `assets/SignatureKiller/origin.apk` |
| 内嵌原包 | 移除原版的 `assets/origin.apk`，改放入 `assets/SignatureKiller/origin.apk`（作为 SignatureKiller 的底包） |
| 新增 SDK | 百度地图 SDK `libBaiduMapSDK_base/map_v7_5_3.so` |
| dex 变化 | 移除原壳 `classes4.dex`；`classes.dex/2/3` 内容有变（含注入的 KillerApplication） |
| 华为能力 | 移除 Huawei ScanKit 相关组件/meta-data（`com.huawei.hms.*`） |

### 改版与内嵌 origin 的精确对比（embedded_origin_vs_modified）
- 仅 6 项新增 / 3 项移除 / 4 项变更 —— 全部为签名绕过注入 + 证书替换，**不含业务资源差异**。
- 佐证：`assets/SignatureKiller/origin.apk` 就是改版改造前的真实底包。

---

## 二、签名绕过注入细节

**入口注入**：`com.kingosoft.activity_kb_common.BaseApplication` 的超类由 `android.app.Application` 改为 `bin.mt.signature.KillerApplication`（jadx 与 smali 双向确认，`modified/apktool/smali_classes3/.../BaseApplication.smali` 第 2 行 `.super Lbin/mt/signature/KillerApplication;`）。

**KillerApplication**（classes3.dex，来源 GitHub `L-JINBIN/ApkSignatureKillerEx`）静态块执行：

- `killPM()` — 硬编码原版 `KINGOKEB` 证书（Base64），反射替换 `PackageInfo.CREATOR`，使其 `createFromParcel` 时把目标包名的签名/签名信息替换为原版证书；Android 9+ 用 LSPosed `HiddenApiBypass` 豁免隐藏 API；清空 `Parcel.mCreators` / `sPairedCreators` / `PackageManager.sPackageInfoCache`。
- `killOpen()` — `System.loadLibrary("SignatureKiller")`，读取 `/proc/self/maps` 定位真实 apk 路径，从 `assets/SignatureKiller/origin.apk` 解压内嵌底包到 `/data/data/<pkg>/origin.apk`，再经 native `hookApkPath()` 把 apk 路径 hook 到解压出的底包。

**注入组件清单**（`modified/jadx/sources` 相对 `embedded_origin` 独有）：
```
bin/mt/signature/KillerApplication.java
mt/Log22A16D.java  Log25EB87.java  Log5A0B53.java  LogA704BA.java  LogBE294D.java  LogE0E388.java
org/lsposed/hiddenapibypass/*  (HiddenApiBypass 隐藏 API 绕过)
```

## 三、业务篡改："觅Ta"服务开关校验绕过

**判定方法**：对 com/kingosoft 下的差异文件做归一化 diff（混淆字段 `f42801a→f42819a`、寄存器变量、数字字面量全部归一化），排除 jadx 反编译噪声（`JADX WARN`、寄存器重命名、字符串拼接差异）。最终确认 **5 个类存在同一手法的真实业务篡改**。

### 篡改手法（统一）
原版逻辑：
```java
if (json.get("mita").equals("1")) {     // mita == "1" 表示对方已开启【觅Ta】服务
    refreshList();                       // 正常刷新/跳转
} else {
    c2("1");                             // 标记"未开启"
    new Dialog().l("亲，温馨提示：")
        .i(name + "未开启【觅Ta】服务，无法查看ta的信息")
        .k("确定", ...).show();          // 弹窗阻止查看
}
```
改版逻辑：
```java
if (json.get("mita").equals("1")) {}     // ← 条件被掏空，原 else 弹窗被删除
refreshList();                            // ← 无条件执行
```

### 受影响类与删除的弹窗
| 类（`com.kingosoft.activity_kb_common.ui.activity.*`） | 被删除的弹窗文案 |
|---|---|
| `new_wdjx.new_kebiao.TeaInfoActivity` | "未开启【觅Ta】服务，无法查看ta的信息" |
| `new_wdjx.new_kebiao.ClassmateInfoActivity` | "您的/对方的觅Ta开关未开启，不能查看他人课表"；"未开启【觅Ta】服务，无法查看ta的信息" |
| `new_wdjx.new_kebiao.TdkbActivity` | "未开启【觅Ta】服务，无法查看ta的信息" |
| `new_wdjx.new_kebiao.MitaNewActivity` | "未开启【觅Ta】服务，无法查看ta的信息" |
| `new_wdjx.new_kebiao.MitaNewListActivity` | "未开启【觅Ta】服务，无法查看ta的信息" |

> 注：Tdkb/MitaNew/MitaNewList 三个类判定的字段是 `state`（响应 JSON 的 `state=="1"`），语义与 `mita` 等价——均为"觅Ta 开关是否开启"。

### 业务影响
改版用户在查看他人课表、个人信息、同学列表时，**不再受对方【觅Ta】服务开关限制**。原版中"对方未开启→客户端弹窗阻断+服务端不返回信息"的校验，被改版客户端掏空成"无条件请求并展示"。属**功能越权**改动。

## 四、排除的"伪差异"

- **317 个文件**经归一化后仅剩 `JADX WARN` 注释/寄存器重命名/字符串拼接差异 → 纯反编译噪声。
- `FdybsdtShActivity` — `str3`/`str2` 临时变量分配差异，逻辑等价。
- `BaseApplication` 中 `f42801a→f42819a`、`k0.f42809h→f42827h` — 混淆字段编号因重打包偏移，值语义不变。
- 推送 SDK（cn/jiguang、cn/jpush、com/xiaomi）、okhttp、room、百度等第三方库差异 — SDK 内部实现/反编译差异，非改版者有意改动。

## 五、分析工作流（可复现）

```bash
# 1. 结构对比（ZIP 条目）
python3 tools/archive_diff.py 原版.apk 改版.apk --output comparison/x.json
# 2. 安全清单对比（需先 apktool d 出明文 Manifest）
python3 tools/manifest_diff.py analysis/original/apktool/AndroidManifest.xml \
    analysis/modified/apktool/AndroidManifest.xml --output comparison/y.json
# 3. jadx 源码归一化 diff（排除混淆噪声，定位真实逻辑改动）
python3 /tmp/norm_diff.py    # 归一化后 diff 整棵源码树
python3 /tmp/show_diff.py <相对路径>   # 查看单个文件真实差异
```
