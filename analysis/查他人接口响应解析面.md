## 0. 本轮新增结论（TL;DR）

1. **响应进入 Java 回调前要过三道处理**（此前只记了第一道）：整包 AES 解密 → `t9.m.e` 容错 JSON 修复 → `t9.m.d` 的 `*_desn` 字段级解密。第三道是**通用字段加密通道**：服务端只要下发 `xxx_desn`，客户端会自动解出并覆盖成 `xxx`，回调/Bean/native 看到的是明文。
2. **信息页/教师页的 `mita` 闸门是 fail-open**：`getString("mita")` 抛异常时 `z10` 被置 `true`，仍然调用 native 行构造器 `G2(str)` / `C2(str)` 渲染整包响应。即「响应缺 `mita` 键」不会被当成未开启。
3. **信息页主请求 = `baseInfoServlet?step=other` 的证据升级为「强」**：`ClassmateInfoActivity.l/m` 与 `TeaInfoActivity.j/k` 读取的键集 `{mita,xm,xb,uuid}` 是 `step=other` 真机 18 键样本的子集；`mita` 键不出现在 `getMITAWithOther`（只有 `state/msg`），同页调用链上唯一候选就是 `e2/a.l/m/n`。仍缺抓包直证，但已不是「靠 435/452 旧比对」的弱推断。
4. **名单链路是双 schema**：服务端可能下发 `{"classmatesList":[...]}`（旧）或 `{"resultSet":[...]}`（新）。旧 schema 由 `t9.m.b` 在客户端转成 `resultSet` 并注入 `uuid = xxdm + "_" + yhxh`；转换开关是 `wsxk.zx.d.c`（值为 `"0"` 时转换）。
5. **`patch_roster.py` 的语义被 smali 直证为正确**：在 `Home_F$x.callback` 的 tdkb 分支处，`p1` 已被 `getString("resultSet")` 覆盖（失败时被 `move-object p1, v0` 置 `"[]"`），所以插入 `move-object v0, p1` 传的是名单数组，不是原始响应。454 反汇编现场：`/tmp/qx_smali/out/smali/.../Home_F$x.smali:107-145`。
6. **两个教师 JID 形态并存**：`e2/a.b`（学友圈入口）用 `jsdm` 拼 JID，`e2/a.c/d`（信息页/扫码）用 `userid` 拼。→ `GetTeaResume` 的 `jsid` 两个候选都试，是对的设计。
7. **`GetTeaResume` 前的「查自己」确实是残留**：`x3/b.a` 把 `baseInfoServlet`（无 step）响应 Gson 成 27 字段 `UserInfoBean`（含 `sfzh/gkksh/zzmm/jtcyset`），`m()` 只用 `userId/usertype/userid/jsid` 四个参数，**`userInfoBean` 从未被读**。解析面宽、消费面为零。
8. **探测版有 4 个未覆盖端点**：`getKb&step=skbjmc`（名单）、`oriHd_kc&step=getCourse_Detail_hd`、`getSettings&step=getMITA`（目标 userId）、`kingo_course&step=course_shoucang_*`。前两个正是「他人课程详情/名单」的核心，建议下一版探测弹窗补上（本文 §7 给参数）。

## 4. 名单链路专章：`getKb&step=skbjmc`

### 4.1 请求（Java 直证）

`Home_F.java:2220-2240`（`I0`）与 `:2320-2345`（`K0`）两处同构：

```
GET {serviceUrl}/wap/wapController.jsp
  userId   = 自己 userid
  usertype = 自己 usertype
  action   = getKb
  step     = skbjmc
  skbj     = courseBean.getSkbj()      ← 教学班号（不是行政班 bjdm）
  xnxq     = 学年+学期
  xn, xq   = 学年 / 学期
```

- **所有课表模式共用**：wdkb / jskb / bjkb / tdkb 都在打开课程详情前发这一条；来源模式只影响本地 Intent 分流，不进业务参数。
- 没有 `bjdm`、没有 `rs`、没有目标用户 id → 服务端只能按 `skbj`（教学班）判断是否下发名单。

### 4.2 响应双 schema 与客户端加工

`Home_F$x.callback`（`Home_F.java:1690-1760`）：

```
str --(wsxk.zx.d.c == "0")--> t9.m.b(str, "yhxh", xxdm)
      // 输入 {"classmatesList":[{...}]}
      // 逐项读 yhxh，注入 uuid = yhxh.startsWith(xxdm+"_") ? yhxh : xxdm+"_"+yhxh
      // 输出 {"resultSet":[...]}   （t9/m.java:67-89）
str --JSONObject.getString("resultSet")--> p1
p1 --tdkb 分支（补丁后）--> Intent.putExtra("classmatesList", p1)
```

- 新 schema 直接给 `resultSet`，跳过 `t9.m.b`（此时 `wsxk.zx.d.c != "0"`）。
- 旧 schema 的 `classmatesList` 项只需 `yhxh`；`uuid` 是客户端合成的，不在服务端响应里。
- `t9.m.b` 只在 `classmatesList` 存在时工作；若响应已是 `resultSet` 而开关仍是 `"0"`，`new JSONObject(str).getJSONArray("classmatesList")` 抛异常 → `validate`/`callback` 链会把异常留给上层 → `p1` 可能为 `"[]"`。

## 5. 信息页主请求归属：证据升级

旧口径（`觅Ta可查字段清单.md` §5）：URL 在 native，「= step=other」靠 `t9/t0` 闸门 + 435/452 旧比对，标「高置信非直证」。本轮补三条：

1. **键集匹配**：`ClassmateInfoActivity.l/m` 读 `mita/xm/xb/uuid`；真机教师 `step=other` 样本顶层键含 `mita/xm/xb/uuid`（18 键宽行）。
2. **排他性**：`getMITAWithOther` 响应只有 `state/msg`（真机样本），不含 `xm/xb/uuid/mita`；`getMITA` 只有 `state`。同页链路上没有第二个可见端点能提供这组键。
3. **调用链**：`t9/t0` 闸门通过后 Java 直调 `e2/a.l/m/n`，三者都是 `step=other`；信息页由这些调用拉起，页面内再发的主请求只可能是同族接口或 native 重放。

→ 证据等级改为 **强（键集匹配 + 排他性 + 同页调用链）**；仍建议真机抓包做最终直证（一次信息页应出现两条 `baseInfoServlet`：闸门调用的 `step=other` + 页面内 native 主请求）。
